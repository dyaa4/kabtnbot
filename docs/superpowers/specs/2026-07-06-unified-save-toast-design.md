# زر حفظ موحد + Toast

**التاريخ:** 2026-07-06 · **الحالة:** معتمد

## المشكلة

تبويب الإعدادات فيه أربعة نماذج ولكل منها زر حفظ خاص — مربك. والتغذية الراجعة
(بانر SaveStatus أعلى الصفحة) قد لا تكون مرئية عند الحفظ من أسفل الصفحة.

## التصميم

1. **Toast**: `ToastProvider` + `useToast()` في `components/Toast.tsx`،
   يُركّب في App.tsx. إشعار أسفل-وسط، أخضر للنجاح وأحمر للفشل (مع تفاصيل
   الخادم عند توفرها)، اختفاء تلقائي ~3.2s، `aria-live="polite"`. توست الخطأ
   يحمل `data-testid="save-error"` (توافقاً مع الاختبارات القائمة). يحل محل
   `SaveStatus` الذي يُحذف.
2. **SaveBar**: شريط لاصق (`sticky bottom-4`) بزر حفظ واحد (type=submit) —
   يُستخدم داخل `<form>`. عند تمرير `dirty` يعرض «لديك تغييرات غير محفوظة» /
   «كل التغييرات محفوظة» ويعطّل الزر إن لم توجد تغييرات.
3. **SettingsTab**: النماذج الأربعة (الصوتي، لغة البوت، الرول الإداري،
   الملخص) تُدمج في `<form>` واحد ينتهي بـSaveBar؛ حفظ واحد يرسل PATCH
   مجمعاً. dirty = isDirty للنموذج الصوتي + مقارنة بقية الحقول بخط الأساس
   من الخادم. بطاقة ملف البوت تبقى خارج النموذج (رفع فوري).
4. **WelcomeTab/ProtectionTab**: زر الحفظ السفلي يُستبدل بـSaveBar
   (Protection مع dirty حقيقي من react-hook-form، وWelcome بلا مؤشر)،
   والنجاح/الفشل عبر Toast.
5. مفاتيح ترجمة جديدة (×6): `settings.unsaved`, `settings.allSaved`.

## الاختبارات

toast يظهر عند النجاح وعند الفشل (مع التفاصيل)، الإعدادات ترسل PATCH واحداً
مجمعاً بزر واحد، الزر معطّل بلا تغييرات ويتفعل عند التعديل، وتحديث كل
الاختبارات التي كانت تنقر أزراراً متعددة أو تقرأ SaveStatus.

# GameBot v1.5 — Web-Dashboard: Design-Spezifikation

**Datum:** 2026-07-05
**Status:** Genehmigt (Brainstorming-Session)
**Basis:** v1-Spec §7 (`2026-07-04-gamebot-v1-design.md`) — dort als Anforderung verankert.

## 1. Überblick

Web-Plattform für GameBot: Landing-Page + Verwaltungs-Dashboard. Server-Admins loggen sich per Discord OAuth2 ein, sehen alle Server, in denen sie berechtigt sind UND der Bot Mitglied ist, und verwalten dort Einstellungen, Leaderboard, Matches und Kontingente. Kostenlos für alle; Premium wird im Datenmodell vorbereitet, Stripe folgt in v1.6.

### Entscheidungen der Session

| Frage | Entscheidung |
|---|---|
| Umfang | Volle Verwaltung (inkl. Match-Abbruch, Punktkorrektur) + Landing-Page + Premium-**Vorbereitung** |
| Stripe/Premium-Verkauf | **v1.6** (eigene Design-Runde: Leistungen, Preis) — nicht in v1.5 |
| Sprache | Arabisch (Standard, RTL) + Englisch, Umschalter ab Start |
| Architektur | **Ansatz A**: eine Fullstack-App `apps/web` (Express: OAuth + API + SPA-Auslieferung), eigener Prozess neben dem Bot, teilt `@gamebot/db` + `@gamebot/shared` |

## 2. Architektur

```
apps/web/
├── server/          # Express: OAuth-Flow, /api/*, statische SPA-Auslieferung
│   ├── auth/        # Discord OAuth2 (identify + guilds), JWT-Session-Cookie
│   ├── discord/     # DiscordRest-Interface (REST mit Bot-Token) + Fake für Tests
│   ├── routes/      # me, guilds, config, leaderboard, matches, usage, adjust
│   └── middleware/  # requireSession, requireGuildAccess (+ 60s Berechtigungs-Cache)
└── client/          # React + Vite + Tailwind SPA (React Router, React Query)
```

- Eigener Prozess (`pnpm --filter @gamebot/web dev|start`), Port `WEB_PORT` (Default 3000).
- SPA und API auf derselben Origin → kein CORS.
- Discord-Zugriffe des Servers ausschließlich über das `DiscordRest`-Interface (Bot-Token) — testbar per Fake-Implementierung.

## 3. Auth & Berechtigungen

- **Flow:** `/auth/discord` → Discord (Scopes `identify`, `guilds`, `state`-Param gegen CSRF) → `/auth/callback` → Code-Tausch → Session-JWT im httpOnly-Cookie (SameSite=Lax, 7 Tage). `/auth/logout` löscht das Cookie.
- **Session-Inhalt:** Discord-User-ID, Username, Avatar-Hash, verschlüsselter User-Access-Token (für Guild-Listen-Refresh).
- **Server-Berechtigung** (identisch zur `/settings`-Regel im Bot). Ein Server ist verwaltbar, wenn:
  1. Bot ist Mitglied (`GET /guilds/{id}` mit Bot-Token → 200), **und**
  2. User hat `MANAGE_GUILD` (Permissions-Bitfeld aus OAuth-`/users/@me/guilds`) **oder** trägt die konfigurierte `admin_role_id` (`GET /guilds/{id}/members/{userId}` mit Bot-Token).
- **Durchsetzung serverseitig pro Request:** `requireSession` → `requireGuildAccess(guildId)`; Guild-IDs vom Client wird nie vertraut. Ergebnisse pro User 60 s im Speicher gecacht (Rate-Limits).

## 4. API (`/api`, Zod-validiert mit geteilten Schemas)

| Endpunkt | Zweck |
|---|---|
| `GET /me` | Eingeloggter User (Name, Avatar) |
| `GET /guilds` | Verwaltbare Server (ID, Name, Icon) |
| `GET /guilds/:id/config` | Aktuelle `GuildConfig` |
| `PATCH /guilds/:id/config` | Patch-Semantik wie `/settings` (nur gesetzte Felder; Arrays ersetzt; `GuildConfigSchema`-Revalidierung) |
| `GET /guilds/:id/leaderboard` | Top-Spieler (`topPlayers`) |
| `GET /guilds/:id/matches` | Aktives Match + letzte 10 abgeschlossene/abgebrochene (neue Repo-Funktion `recentMatches(guildId, limit = 10)`) |
| `GET /guilds/:id/usage` | Heutige Kontingente + wirksame Limits |
| `POST /guilds/:id/matches/:matchId/cancel` | Match abbrechen: `cancelMatch`-Repo + Temp-Voice-Räume und Lobby-Buttons via Discord-REST aufräumen |
| `POST /guilds/:id/players/:userId/adjust` | Punktkorrektur `{delta: int, min -1000, max 1000}` → neue Repo-Funktion `adjustPlayerPoints(guildId, userId, delta)` |

Fehlerformat einheitlich `{ error: { code, message } }`. Rate-Limiting auf `/auth/*`.

## 5. Datenmodell-Erweiterungen (packages)

- **`@gamebot/shared` — `GuildConfigSchema` erweitert:**
  `premium: { active: boolean = false, listen_minutes_override: number|null = null, ai_questions_override: number|null = null }`
- **`@gamebot/shared` — neue Helper-Funktion:**
  `effectiveQuotas(config): { listen_minutes_per_day, ai_questions_per_day }` — liefert Overrides, wenn `premium.active`, sonst die Basiswerte.
- **`apps/bot` — Quota-Layer** (`lib/quotas.ts`) nutzt ab sofort `effectiveQuotas` statt der Rohwerte. Keine weitere Bot-Änderung.
- **`@gamebot/db` — neue Repo-Funktion:** `adjustPlayerPoints(guildId, userId, delta)` (Upsert, `$inc: points`).
- **v1.6-Andockpunkt:** Stripe-Webhook muss später nur `premium.active`/Overrides setzen.

## 6. Frontend

### Seiten
- **`/` Landing:** Hero (Name + Slogan), Feature-Karten (Kustoms, Sprach-KI mit Dialekten, Leaderboard), „Bot einladen"-Button (Invite-URL mit `permissions=19926032`), „Premium — قريبًا / Coming soon"-Sektion, Login-Button, Footer.
- **`/app`:** Server-Grid (Icons + Namen der verwaltbaren Server).
- **`/app/:guildId`** — vier Tabs:
  1. **Übersicht:** Kontingent-Fortschrittsbalken (Zuhör-Minuten, KI-Fragen, aus `/usage`), aktives Match mit Abbrechen-Button.
  2. **Einstellungen:** Voice-Formular (enabled, Weckwort, Dialekt, erlaubte Kanäle) + Customs-Formular (Punkte, Admin-Rolle); react-hook-form + geteilte Zod-Schemas.
  3. **Leaderboard:** Top-Spieler mit Avataren; Punktkorrektur-Dialog (±) pro Zeile.
  4. **Matches:** laufend + letzte Ergebnisse.

### i18n & RTL
Arabisch (Standard, `dir="rtl"`) + Englisch, Umschalter im Header, persistiert in localStorage. JSON-Wörterbücher (`ar.json`, `en.json`), alle UI-Texte darüber. Tailwind mit logischen Properties (`ms-`/`me-`).

### State & Fehler
React Query (Invalidierung nach jedem PATCH/POST); Toast bei API-Fehlern; 401 → Login-Redirect; 403 → zurück zur Serverliste mit Hinweis.

## 7. Sicherheit

- httpOnly-Cookie, SameSite=Lax; OAuth-`state`; Sessions-Secret aus `.env`.
- Alle Guild-Routen doppelt geschützt (Session + Guild-Access), Repos erzwingen `guildId` ohnehin.
- Punktkorrektur-Delta begrenzt (±1000), Zod-validiert.
- Keine Bot-/User-Tokens im Client; Discord-REST nur serverseitig.

## 8. Tests

- **API (Schwerpunkt, Vitest + Supertest + mongodb-memory-server + Fake-DiscordRest):** Zugriffsverweigerung (kein MANAGE_GUILD/keine Admin-Rolle → 403; fremde Guild-ID → 403; Bot nicht Mitglied → nicht in Liste), Config-PATCH-Validierung (ungültiger Dialekt → 400), `adjustPlayerPoints`-Grenzen, Match-Cancel-Pfad, `effectiveQuotas`-Mathematik (Premium an/aus, Overrides null).
- **Frontend:** Formular-Validierung (Weckwort-Grenzen), i18n/RTL-Smoke (ar ↔ en Umschaltung setzt `dir`).

## 9. Neue Umgebungsvariablen

```
DISCORD_CLIENT_SECRET=   # OAuth2 (Portal → OAuth2 → Client Secret)
WEB_BASE_URL=http://localhost:3000
WEB_PORT=3000
SESSION_SECRET=          # JWT-Signierung Dashboard-Sessions
```
Redirect-URI `WEB_BASE_URL/auth/callback` muss im Discord-Portal eingetragen werden.

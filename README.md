# Kabtn (كابتن)

> ملاحظة: أسماء الحزم والمجلدات والمتغيرات البيئية في الكود تبقى `gamebot` كما هي —
> إعادة التسمية هذه تخص العلامة التجارية (الاسم الظاهر للمستخدم) فقط، وليست إعادة تسمية
> للحزم أو المجلدات.

بوت Discord عربي لإدارة الكستمز (المباريات الودية) داخل السيرفر، مع مساعد صوتي بالذكاء
الاصطناعي يدخل روم الفويس، يسمع كلمة تنبيه، ويرد بصوت طبيعي بلهجات عربية مختلفة.

## المزايا

- **الكستمز**: `/custom create` لفتح لوبي انضمام بالأزرار، توزيع فرق عشوائي أو متوازن
  بالنقاط، تحريك اللاعبين تلقائيًا إلى رومات صوتية مؤقتة، تسجيل النتيجة ومنح النقاط،
  وإلغاء المباراة عند الحاجة.
- **لوحة الصدارة والبروفايل**: `/leaderboard` و `/profile` لعرض نقاط اللاعبين وسجلهم.
- **المساعد الصوتي**: `/join` يدخل البوت الروم ويبدأ الاستماع لكلمة التنبيه (افتراضيًا
  «يا بوت …»)، يفهم الطلب عبر تحويل الصوت إلى نص (Groq)، يرد بالذكاء الاصطناعي (Groq أو
  Gemini كخيار احتياطي)، ثم يتحول الرد إلى صوت طبيعي (ElevenLabs) ويُشغَّل في نفس الروم.
- **أوامر نصية للذكاء الاصطناعي**: `/ask` (يرد نصيًا وصوتيًا إن كان البوت في الفويس)
  و `/chat` (رد نصي فقط).
- **إعدادات لكل سيرفر**: `/settings` للتحكم بتفعيل الصوتي، كلمة التنبيه، اللهجة، الرومات
  المسموحة، نقاط الفوز/الخسارة، والرول الإداري.
- **حصص استخدام يومية لكل سيرفر** لضبط تكلفة الـ AI (راجع "الحصص الافتراضية" أدناه).

## المتطلبات الأساسية (Prerequisites)

| المتطلب | الحد الأدنى | ملاحظة |
|---|---|---|
| Node.js | **22.12+** | حزمة `@discordjs/voice@0.19.2` تفرض `engines.node >= 22.12.0`، وحقل `engines` في `package.json` الجذري مضبوط على `>=22.12` تبعًا لذلك — استخدم هذا الإصدار محليًا وفي أي بيئة تشغيل. |
| pnpm | 9.x | حسب `packageManager` في `package.json` (`pnpm@9.15.0`). |
| MongoDB | **6.0+** | رابط اتصال (URI) من MongoDB Atlas أو أي MongoDB متوافق — الإصدار 6.0 أو أحدث مطلوب لأن الفهرس الفريد لمنع تعدد المباريات النشطة يستخدم partial filter مع `$in`. |
| تطبيق Discord (Developer Portal) | — | راجع القسم التالي لإعداد الصلاحيات والـ Intents. |
| مفاتيح API | GROQ إلزامي، ELEVENLABS إلزامي للصوت، GEMINI اختياري | راجع "المفاتيح" أدناه. |

### إعداد تطبيق Discord

في [Discord Developer Portal](https://discord.com/developers/applications)، لتطبيق البوت:

1. **Privileged Gateway Intents** (تبويب Bot): فعّل:
   - `SERVER MEMBERS INTENT` (مطابق لـ `GuildMembers` في الكود — يجب تفعيله يدويًا، معطل
     افتراضيًا).
   - `Guilds` مفعّل تلقائيًا مع أي بوت (لا يحتاج تفعيل يدوي).
   - `GuildVoiceStates` جزء من الـ Intents الافتراضية غير المميزة (non-privileged)، لا
     يحتاج تفعيلًا يدويًا في البوابة، لكنه مفعّل في كود العميل (`client.ts`).
2. **صلاحيات البوت (Bot Permissions)** عند إنشاء رابط الدعوة (OAuth2 URL Generator، Scope
   `bot` + `applications.commands`):
   - `Manage Channels` (لإنشاء/حذف الرومات الصوتية المؤقتة للمباريات).
   - `Move Members` (لنقل اللاعبين بين الرومات).
   - `Connect` و `Speak` (للانضمام للفويس وتشغيل الصوت).

### مفاتيح الـ API

| المفتاح | إلزامي؟ | الاستخدام |
|---|---|---|
| `DISCORD_TOKEN` / `DISCORD_CLIENT_ID` | نعم | توكن البوت ومعرف التطبيق. |
| `MONGODB_URI` | نعم | تخزين إعدادات السيرفر، المباريات، النقاط، والحصص اليومية. |
| `GROQ_API_KEY` | نعم | تحويل الصوت إلى نص (STT) وتوليد ردود الذكاء الاصطناعي. |
| `ELEVENLABS_API_KEY` | نعم (للصوت) | تحويل النص إلى صوت (TTS) الذي يسمعه اللاعبون في الفويس. |
| `GEMINI_API_KEY` | اختياري | مزود احتياطي للذكاء الاصطناعي إذا فشل Groq. |

جميع المفاتيح موجودة كأسطر فارغة في `.env.example`.

## خطوات التشغيل

```bash
cp .env.example .env
# ثم افتح .env واملأ القيم: DISCORD_TOKEN, DISCORD_CLIENT_ID, MONGODB_URI,
# GROQ_API_KEY, ELEVENLABS_API_KEY (و GEMINI_API_KEY اختياريًا)

pnpm install
pnpm build
pnpm deploy:commands   # يسجل أوامر السلاش (Slash Commands)؛ عيّن DISCORD_GUILD_ID
                       # في .env لتسجيل فوري على سيرفر تجريبي واحد، أو اتركه فارغًا
                       # للتسجيل العام (قد يستغرق حتى ساعة على مستوى Discord)
pnpm dev               # تشغيل البوت (وضع تطوير عبر tsx)؛ للإنتاج استخدم:
                       # pnpm --filter @gamebot/bot start
```

عند التشغيل الناجح، يجب أن ترى في السجل:

```
[DB] Connected
[Ready] Logged in as <اسم البوت>
```

### التشغيل عبر Docker

يوفر المشروع `Dockerfile` جاهز:

```bash
docker build -t gamebot .
docker run --env-file .env gamebot
```

الصورة الأساسية `node:22.12-slim` (تطابق متطلب `@discordjs/voice` أعلاه). البناء يشمّل
تثبيت الاعتماديات (`pnpm install --frozen-lockfile`)، بناء كل الحزم (`pnpm build`)، ثم
تقليم اعتماديات التطوير (`pnpm prune --prod`). لا حاجة لحزم `apt` إضافية: ثنائي `ffmpeg`
يأتي مع حزمة `ffmpeg-static` عبر npm، و `opusscript` و `libsodium-wrappers` جافاسكربت/WASM
خالص بدون بناء أصلي (`node-gyp`).

> ملاحظة: هذا الريبو لا يتضمن تنفيذًا فعليًا لـ `docker build` كجزء من التحقق الآلي (بيئة
> التطوير الحالية بدون Docker daemon) — التحقق من نجاح البناء متروك للمشغّل (operator).

## قائمة الأوامر

| الأمر | الوصف |
|---|---|
| `/custom create` | فتح لوبي مباراة كستم جديدة (اختيار اللعبة، حجم الفريق، وطريقة التوزيع)، مع أزرار انضمام/بدء. |
| `/custom result` | تسجيل نتيجة المباراة النشطة (الفريق الفائز) ومنح النقاط، مع حذف الرومات المؤقتة. |
| `/custom cancel` | إلغاء المباراة النشطة الحالية. |
| `/leaderboard` | عرض لوحة الصدارة حسب النقاط. |
| `/profile` | عرض بروفايل وسجل اللاعب. |
| `/join` | إدخال البوت لروم الفويس الحالي وبدء الاستماع لكلمة التنبيه. |
| `/leave` | إخراج البوت من الفويس. |
| `/speak` | جعل البوت يقرأ نصًا معينًا بصوت مسموع في الفويس. |
| `/ask` | سؤال الذكاء الاصطناعي؛ يرد نصيًا، ويردّ صوتيًا أيضًا إذا كان البوت متصلًا بالفويس. |
| `/chat` | دردشة نصية فقط مع الذكاء الاصطناعي (بدون رد صوتي). |
| `/settings view` | عرض إعدادات السيرفر الحالية (الصوتي، الكستمز، الحصص اليومية). |
| `/settings voice` | ضبط تفعيل الصوتي، كلمة التنبيه، اللهجة، والرومات المسموحة. |
| `/settings customs` | ضبط نقاط الفوز/الخسارة والرول الإداري للكستمز. |
| `/ping` | فحص سرعة استجابة البوت (latency). |

جميع أوامر `/settings` وإدارة الكستمز محصورة بمن يملك صلاحية `Manage Guild` أو الرول
الإداري المحدد عبر `/settings customs admin_role`.

## الحصص الافتراضية (Default Quotas)

لكل سيرفر يوميًا (تُعاد للصفر كل يوم UTC، قابلة للتخصيص عبر إعدادات السيرفر مباشرة في
قاعدة البيانات — لا يوجد أمر سلاش حاليًا لتغييرها):

- **الاستماع الصوتي**: 60 دقيقة/يوم.
- **أسئلة الذكاء الاصطناعي**: 50 سؤال/يوم.

## استخدام كلمة التنبيه الصوتية

بعد `/join`، يستمع البوت في الروم لكلمة تنبيه قابلة للتخصيص (الافتراضي: **«يا بوت»**).
مثال: قل «**يا بوت السرعة**» ليجيب البوت صوتيًا على سؤالك. لتغيير كلمة التنبيه أو اللهجة
لكل سيرفر:

```
/settings voice wake_word:يا روبوت dialect:مصرية
```

اللهجات المتاحة حاليًا: خليجية، سورية، مصرية، فصحى.

## التحقق الحي (Live Smoke Test) — مطلوب من المشغّل

هذا الريبو لا يملك بيانات اعتماد حقيقية (`DISCORD_TOKEN`, `MONGODB_URI`, مفاتيح الذكاء
الاصطناعي)، لذا **لم يتم تنفيذ** أي اختبار حي فعلي، ويجب على المشغّل تنفيذ الخطوات التالية
يدويًا بعد ملء `.env` بقيم حقيقية:

1. `pnpm deploy:commands` مع تعيين `DISCORD_GUILD_ID` على سيرفر تجريبي، لتسجيل فوري
   للأوامر.
2. `pnpm dev` — يجب أن تظهر رسالتا `[DB] Connected` ثم `[Ready] Logged in as ...`.
3. داخل Discord:
   - `/ping` → رد بزمن الاستجابة.
   - `/custom create` → يظهر لوبي؛ انضمام حسابين؛ الضغط على بدء → إنشاء رومين صوتيين
     مؤقتين ونقل الأعضاء إليهما.
   - `/custom result` → منح النقاط وحذف الرومات المؤقتة.
   - `/leaderboard` → يظهر فيها اللاعبان.
4. `/join` في روم صوتي → البوت ينضم؛ قول «يا بوت السرعة» → رد صوتي مسموع (يتطلب مفاتيح
   `GROQ_API_KEY` و `ELEVENLABS_API_KEY` فعلية).
5. `/settings voice dialect:مصرية` ثم `/settings view` → يجب أن تظهر القيمة محفوظة.

> **حالة هذه الخطوة في هذا التسليم: BLOCKED-for-operator.** لا توجد بيانات اعتماد Discord
> أو MongoDB أو مزودي الذكاء الاصطناعي في بيئة التطوير الحالية، ولم يتم تنفيذ أي محاكاة أو
> نتائج وهمية بديلة. التحقق الآلي المنفّذ فعليًا يقتصر على `pnpm test` و `pnpm build` (راجع
> سجل التحقق في `.superpowers/sdd/task-16-report.md`).

## لوحة التحكم (Dashboard)

بالإضافة للبوت، يوفر المشروع تطبيق ويب (`apps/web`) — لوحة تحكم بواجهة عربية/إنجليزية
(RTL/LTR) لإدارة إعدادات السيرفر، متابعة لوحة الصدارة، وإدارة المباريات، دون الحاجة
لأوامر Discord.

### متغيرات البيئة الإضافية

بالإضافة لمتغيرات البوت أعلاه، تحتاج لوحة التحكم للمتغيرات التالية في `.env`:

| المتغير | إلزامي؟ | ملاحظة |
|---|---|---|
| `DISCORD_CLIENT_SECRET` | نعم | سر تطبيق Discord (Client Secret)، من تبويب OAuth2 في الـ Developer Portal. |
| `SESSION_SECRET` | نعم | أي نص عشوائي بطول 32 حرفًا أو أكثر، يُستخدم لتوقيع جلسة تسجيل الدخول. يمكن توليده محليًا مثلًا بـ `openssl rand -hex 32`. |
| `WEB_PORT` | لا (افتراضي `3000`) | المنفذ الذي يستمع عليه خادم لوحة التحكم. |
| `WEB_BASE_URL` | لا (افتراضي `http://localhost:3000`) | الرابط الأساسي الذي يُستخدم في بناء رابط الـ OAuth callback. |

### إعداد Redirect URI في Discord Developer Portal

في نفس تطبيق البوت (أو تطبيق منفصل)، من تبويب **OAuth2 → Redirects**، أضف:

```
http://localhost:3000/auth/callback
```

(أو ما يطابق `WEB_BASE_URL` الخاص بك + `/auth/callback` في حال استخدام رابط مختلف أو بيئة
إنتاج).

### تشغيل لوحة التحكم

```bash
# تطوير (يعيد البناء تلقائيًا عند التعديل):
pnpm dev:web

# إنتاج:
pnpm --filter @gamebot/web build
pnpm --filter @gamebot/web start
```

خلف بروكسي عكسي (Reverse Proxy) في بيئة الإنتاج، إعداد `trust proxy` مُهيَّأ مسبقًا على `1`؛
لذا يجب عدم كشف منفذ الخادم مباشرة للإنترنت — اكشف البروكسي فقط.

### قائمة تحقق تشغيلية (Operator Smoke Checklist)

بعد تشغيل الخادم بنجاح وملء بيانات الاعتماد الحقيقية، يجب على المشغّل التحقق يدويًا من:

1. فتح `http://localhost:3000` → صفحة الهبوط تظهر بالعربية واتجاه RTL.
2. الضغط على مبدّل اللغة → الواجهة تتحول للإنجليزية واتجاه LTR.
3. تسجيل الدخول عبر Discord → تظهر شبكة السيرفرات التي أنت مدير فيها والبوت موجود بها.
4. تغيير اللهجة من تبويب الإعدادات، ثم التحقق من الحفظ عبر `/settings view` داخل Discord.
5. تبويب لوحة الصدارة يعرض اللاعبين بعد إجراء كستم؛ زر تعديل النقاط (±) يعمل ويحدّث القيم.
6. إلغاء مباراة نشطة من تبويب النظرة العامة (Overview) → يؤدي لحذف الرومات الصوتية المؤقتة
   فعليًا داخل Discord.
